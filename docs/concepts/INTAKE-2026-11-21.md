## A. App platform (owner: `platform`; evidence: `survey`)
- A1 Wasm-native app context: V8/HTML-class capability, but features are contracts at interface points; wasm does not bind through JS.
- A2 An app that could fetch a page, but speaks its own protocols for everything (not header/SEO).
- A3 Protocol catalog, data-driven, pluggable, not hard-coded: cache with partial invalidation by enumeration, enumerable result sets, REST queries, transports (http, tcp, udp), TLS, post-quantum and self-improvement-resistant surfaces, CA handling, GDPR and US data rules. Omitted protocol = default from the catalog.
- A4 Trust: the app acts for the user and trusts no source it ingests; view/server encryption automated.
- A5 Time-positional events: input as records (start/transition time, payload), handlers read state by timestamp; queue consumed against intervals.
- A6 Scheduling by timestamp comparison, intervals pinned to floored epoch multiples; at-time vs scheduled functions; guards project traces and knock out downstream executions.
- A7 Look: CSS-like styling plus a shader spec following what the browser community settled (WebGPU or newer over WebGL).

## B. Exploration method (owner: `survey`)
- B1 An `explored` catalog: where looked, when, blob kept (noise filtered), location in the blob, ranges not read.
- B2 Deferred breadcrumbs: referenced or inferred resources not followed, attributed to their blob, with confidence (concrete, gist, inferred).
- B3 Coarse runs rank concerns (function, features, security, nomenclature and its meaning for the product); defer the rest to protect the token budget.

## C. Harness philosophy (owner: `context`; seams: `seams`)
- C1 Reduce reasoning where none is needed: the host is data, commands are queries; a collector script replaces many exploring turns.
- C2 Semantic routing: a model states intent in words; policy tags route to a fixed command; the model need not generate parameters.
- C3 Result shaping: the output is the output; follow-on formatting is chosen by command type and params (single-responsibility params); return only what is pertinent (names, not metadata).
- C4 Terse aliases and labels for small models; they carry the params and the tidy-up.
- C5 Buckets: undetermined-state collectors, fixed queries, deferred intent; all results are deferred keyed state; goals fan out into buckets.
- C6 Partially completed turns: pre-filled, slot-like sentences bound to labels and data, so a router can pick references by fuzzy string position.
- C7 Passive markers: items picked or important get external labels; recency picks the proper variant (drift-proofing, renames); fewer hallucinations.
- C8 A helper model, driven by the harness (not helper-of-helper), writes the markers and tags that steer another model.
- C9 Extend with further principles of the same kind; name them in the catalog.
